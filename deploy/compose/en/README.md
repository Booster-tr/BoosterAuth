# Booster Auth installation (Docker Compose)

Run Booster Auth on a single server (or your own computer) in a few minutes.

## Requirements

- Docker Engine 24+ and Docker Compose v2 (Windows/macOS: Docker Desktop)
- At least 4 GB free memory, 10 GB disk
- Internet access (images are pulled from `ghcr.io/booster-tr`)

## 1. Setup

In the folder where you unzipped the package:

```bash
# Linux / macOS
./setup.sh

# Windows (PowerShell)
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

The script asks for:

| Question | Example | Description |
| --- | --- | --- |
| Booster Auth address | `auth.company.com` | The address your applications redirect to for sign-in. **Must be one of the domains in your license.** |
| HTTPS port | `443` | If another service uses 443, e.g. `8443` |
| Panel port and address | `3000`, `http://localhost:3000` | Management panel |
| Administrator e-mail | `it@company.com` | Use a real mailbox if you will enable 2FA |

Passwords and keys are generated randomly and written to `.env`. **Back up the `.env` file and do not share it.**

> **Local trial:** If the address is not in DNS yet, add a `127.0.0.1 auth.company.com` line to the `hosts` file
> (Windows: `C:\Windows\System32\drivers\etc\hosts`, Linux/macOS: `/etc/hosts`).

## 2. Run

```bash
docker compose up -d
```

The first start takes a few minutes while images are pulled. To see the status: `docker compose ps`.

- **Management panel:** the address you gave during setup (default `http://localhost:3000`)
- **Booster Auth (IdP):** `https://<address>/idp` - OIDC discovery: `https://<address>/idp/.well-known/openid-configuration`

Sign in to the panel with the user name **`admin`** and the initial password shown by the setup script; you will be asked to set a new password on first sign-in.

### HTTPS certificate

On first start your own local certificate authority (CA) and a server certificate are generated automatically (`pki/`).
The browser does not know this certificate and shows a warning. Two options:

- **Trial:** add `pki/trust/ca.crt` to your operating system as a "trusted root certificate".
- **Production:** put a reverse proxy (nginx, Traefik, Cloudflare Tunnel, etc.) with your own certificate in front, or
  replace `pki/tls/server.crt` and `server.key` with your own certificate.

## 3. License

The installation starts **without a license**: end-user sign-in works, the management panel is **read-only**.

1. Open **System > License** in the panel. Your installation id is shown there.
2. Click **Get a license**; the licensing portal (`licensing.appnuraymind.com`) opens with your installation id filled in.
3. Create an account on the portal and enter your company and installation details. Get a **free trial** or buy a plan.
4. Paste the license key from the portal into **System > License** in the panel. No service restart is needed.

The license is verified offline; Booster Auth does not connect to a license server.

## E-mail

For sign-up verification, invitation and password reset e-mails, fill in the `MAIL_*` fields in `.env` and run
`docker compose up -d`. If left empty, no e-mail is sent.

## Daily operations

| Task | Command |
| --- | --- |
| Status | `docker compose ps` |
| Logs | `docker compose logs -f booster-idp` |
| Update | `docker compose pull && docker compose up -d --remove-orphans` |
| Stop | `docker compose down` (data is kept) |
| Backup | `docker compose down`, then back up `data/`, `pki/`, `secrets/` and `.env` |

To pin a specific version, change `BOOSTER_VERSION` in `.env` (default `latest`).

If you updated from an older release that included Kafka, you can delete the old Kafka data: `docker volume rm booster-auth_kafka_data`
(the prefix is `COMPOSE_PROJECT_NAME` from `.env`).

## Folders

```
.env               settings and secrets (generated by the setup script)
docker-compose.yml services
init/              start-up scripts (certificates, databases)
data/              PERSISTENT DATA (database, IdP keys)
pki/               local CA and HTTPS certificate
secrets/           IdP signing key
```
